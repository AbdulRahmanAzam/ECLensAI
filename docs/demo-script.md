# ECLens AI — Demo Script

Two timed walkthroughs (3-minute and 7-minute) plus a judge Q&A section with answers grounded in the actual implementation, not aspiration. Both scripts assume the seeded demo state: log in at `/login` as `demo@eclens.ai` / `Demo1234!` (RISK_ANALYST), or `reviewer@eclens.ai` / `admin@eclens.ai` with the same password for the approval/admin steps. Every figure named below is a real seeded number, current as of the last `npm run db:seed` — if the book has since been reset via **Guided Demo → Reset demo data**, the shape holds but exact digits will differ (that's the point: nothing here is hand-typed).

The fastest way to run either script live is **Start Guided Demo** in the top bar — it is the same six-beat story below, as a spotlight tour over the real pages. Use it if you'd rather narrate over the tool than click ahead of it.

## 3-minute script

1. **Land on the Dashboard** (`/dashboard`). Point at the KPI row: gross carrying amount ~PKR 278B, ECL allowance ~PKR 7.07B, coverage 2.55%, Stage 1/2/3 split. Say: "Every number here is a decimal string out of a deterministic engine — nothing is rounded in the browser."
2. **Filter it.** Set Segment to `corporate`. The KPI row, movement bridge, and concentration table all update together, and a chip appears showing the active filter. Say: "One filter, nine charts agree — they all read the same aggregate endpoint the AI copilot's tools also read."
3. **Drill down.** Click a row in "Top ECL drivers" → lands on Exposure 360. Point at the calculation tab: period-by-period marginal PD × LGD × EAD × discount factor, summing to the exact allowance shown on the dashboard.
4. **Ask the Copilot** (`/copilot`, or the Executive Commentary card on the dashboard): "Why did the allowance increase?" Gemini answers with real seeded figures and cites its sources — and if you ask something the evidence doesn't cover, it says so instead of guessing.
5. **Download a report.** Open any approved run (`/ecl-runs`) → **Generate report**. A real PDF downloads: totals, stage breakdown, scenario weights, movements, model assumptions, approval history, page numbers, generation timestamp.

## 7-minute script

Follow the 3-minute script, then add:

6. **Imports** (`/imports`). Show the AI mapping-confidence panel on an unmapped column, and the validation-issues table — every quarantined row carries a row number, field, raw value, and issue code. Nothing is silently repaired.
7. **Scenario Lab** (`/scenarios`). Describe a downside narrative to the AI Scenario Assistant; it proposes PD/LGD multipliers with a rationale, shown as a labelled **proposal**. Open "New version" with the draft prefilled — point at the **Indicative** box: a rough scalar estimate, explicitly not the calculated figure. Save it, then show the new version sitting as **pending approval** — it cannot be selected when creating a run until a REVIEWER approves it.
8. **Approve it** (log in as `reviewer@eclens.ai`). One click, immediately reflected: the badge flips to **approved**, and the version now appears in the ECL Runs scenario picker.
9. **Stage migration** (Dashboard). Point at the matrix: rows are the prior period's stage, columns the current one — the diagonal is "stayed put," everything else is a real transition, matched on exposure id across two snapshots.
10. **Model Governance** (`/model-governance`). Show the active configuration's staging thresholds (90-day default backstop, 30-day SICR backstop) and the version history — editing an assumption creates a new version; it never rewrites a completed run's locked copy.
11. **Audit log** (`/audit-log`). Filter to the actions just taken (scenario approval, report generation) — every one is there with actor, timestamp, and request id.
12. **Reset the demo** (as `admin@eclens.ai`, from the Guided Demo panel). Takes about two minutes; explain what it's doing while it runs — full wipe-and-reseed of the same deterministic dataset — rather than leaving dead air.

## Likely judge questions

| Question | Answer |
| --- | --- |
| Why not let Gemini calculate the ECL number directly? | It can't reach the number: the AI's tool registry has zero mutating or calculating tools — only eight read-only functions that return stored records. Every dollar figure the model ever states is copied from a persisted `EclResult` row; the grounding check (`runner.ts`) rejects any answer that states a number absent from the evidence it was actually given. |
| How do we know this isn't hard-coded or a screenshot? | Ask it a question with a filter combination that hasn't been asked before — the Copilot re-derives the answer from live Postgres rows on every call. Or trigger **Reset demo data** and watch every id in the URL bar change afterward — the whole book is regenerated by a deterministic PRNG, not replayed from a fixture. |
| What happens if the Gemini API key is missing or the call fails? | Every AI surface returns an honest `AI_UNAVAILABLE` state with `result: null` and, on the Copilot specifically, a deterministic fallback answer built from the same stored aggregates — never a fabricated response. Nothing else in the product is affected: staging, calculation, approval, and reporting are pure deterministic code paths with no Gemini dependency. |
| What's the actual ECL formula? | For each exposure and scenario: `ECL = Σ over periods of marginalPD(t) × LGD(t) × EAD(t) × discountFactor(t)`, then `allowance = Σ over scenarios of ECL(scenario) × weight(scenario)`. Stage 1 sums over 12 months; Stage 2/3 sum over the remaining contractual lifetime. The single-period `PD × LGD × EAD × DF` shortcut is computed too, but only ever shown labelled "educational approximation" — never the reported figure. |
| Why PKR and this specific portfolio shape? | The seed models a Pakistani bank's book — five segments (consumer, SME, agriculture, microfinance, corporate), 780 exposures, all three stages represented, three reporting periods with deliberate loan-level churn (new originations and derecognitions) so the movement bridge and stage migration matrix have something real to show. Currency is configurable per organisation; PKR is the seeded default. |
| Is the PDF report real or a mockup? | Real — built server-side with `pdfkit` from the run's own persisted totals at request time, never pre-generated. Refuses to generate for a run with no results (`DRAFT`/`RUNNING`/`FAILED`), and watermarks the page "DRAFT — NOT APPROVED" diagonally whenever the run isn't `APPROVED`. |
| What stops an analyst from approving their own submission? | Four-eyes enforcement server-side: `approveRun`/`rejectRun` refuse when the reviewer id matches the run's creator id, regardless of role — the API returns `RUN_SELF_APPROVAL_PROHIBITED` rather than hiding the button, so the analyst sees why they're blocked. |
| Does the AI ever change data on its own? | No tool in its registry can. Every AI-proposed mapping, staging signal, or scenario draft is stored as a **proposal** and requires an explicit human action through a normal, audited endpoint before it affects anything — the same rule the spec calls "no autonomous mutation," implemented as an architectural property (nothing to override) rather than a prompt instruction (something a clever input could talk around). |

## Fastest manual path (no narration)

Login → Dashboard (glance at KPIs) → filter by segment → click a driver row → Copilot question → Generate report. Under 90 seconds, and it touches the deterministic engine, the analytics layer, the AI copilot, and the reporting pipeline in one line.
